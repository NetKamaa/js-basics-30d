# Async drills

## Состояния запроса и UI

idle — пустой экран  
loading — спиннер / "Загрузка..."  
success — список данных  
error — сообщение об ошибке

## Почему isLoading и error лучше хранить рядом с логикой запроса

`isLoading` и `error` напрямую связаны с жизненным циклом запроса.  
Если хранить их рядом с логикой запроса, состояние приложения становится:

- **предсказуемым** — все стадии запроса находятся в одном месте
- **проще поддерживать** — не нужно искать флаги по разным файлам
- **легче синхронизировать UI** — интерфейс просто смотрит на статус запроса

В проекте это реализовано через поля состояния:

- `requestStatus`
- `requestError`

Например, перед загрузкой состояние переключается в `loading`, а при ошибке — в `error`. Это происходит в одном месте — в экшене загрузки данных. :contentReference[oaicite:0]{index=0}

Так UI может просто читать состояние и решать, что показывать.

## Когда использовать try/catch

`try/catch` нужен для **реальных исключений**, например:

- ошибка сети
- fetch не смог выполнить запрос
- ошибка парсинга JSON
- код явно делает `throw new Error(...)`

Пример из проекта:

```js
try {
  const items = await loadItemsFromApi();
} catch (e) {
  // обработка ошибки
}
```
